# typst-bazel

Bazel rules for [Typst](https://typst.app): compile documents with a
Typst that Bazel downloads, from inputs Bazel knows about.

> [!WARNING]
> typst-bazel is being built. This file describes what works today:
> Bazel downloads Typst and compiles a document from files in one
> repository, with fonts from anywhere, packages you wrote, and packages
> from Typst Universe. It is for Linux and macOS, and has run on macOS
> only.

> [!NOTE]
> This codebase is AI-written. Treat [`docs/rules.md`](docs/rules.md) as
> what the rules promise, and read the code before relying on it for
> anything that matters.

## Choosing a Typst

No registry has the rules yet, so a module gets them from GitHub. In
`MODULE.bazel`:

```starlark
bazel_dep(name = "typst-bazel")
git_override(
    module_name = "typst-bazel",
    commit = "70094cb10cd35419f13106b7547349550538df5c",  # v0.0.1
    remote = "https://github.com/popovicu/typst-bazel.git",
)

typst = use_extension("@typst-bazel//typst:extensions.bzl", "typst")
typst.toolchain(version = "0.15.1")
```

Bazel downloads that release for the machine running the build, the
first time something needs it, and checks it against a pinned SHA-256.
Typst from the host is never used. `typst/private/versions.bzl` lists the
releases to choose from.

To run it by hand:

```bash
bazel run @typst-bazel//typst -- fonts
```

## Compiling a document

```starlark
load("@typst-bazel//typst:defs.bzl", "typst_document")

typst_document(
    name = "report",
    main = "report.typ",
    srcs = [
        "chapters/intro.typ",
        "figures/plot.svg",
        ":numbers.json",  # generated by another rule
    ],
    deps = ["//shared:style"],
)
```

`bazel build :report` writes `report.pdf`. `srcs` and the libraries in
`deps` are every file the document reads by path, from any package of the
repository, generated or not. Typst sees them as one tree laid out like the repository: beside
`report.typ` the chapter is `"chapters/intro.typ"`, and from anywhere the
style is `"/shared/style.typ"`. A file that is not listed is not found.

Files that several documents read go in a library, which brings along
the libraries it reads from in turn:

```starlark
load("@typst-bazel//typst:defs.bzl", "typst_library")

typst_library(
    name = "style",
    srcs = ["style.typ", "logo.svg"],
    deps = ["//shared:colors"],
)
```

A document names it in `deps` and reads its files by path, as it reads
its own `srcs`.

## Packages

A package is a directory with a `typst.toml`, imported by name from
anywhere, another repository included:

```starlark
load("@typst-bazel//typst:defs.bzl", "typst_package")

typst_package(
    name = "house-style",
    manifest = "typst.toml",
    srcs = glob(["src/**"]),
    namespace = "acme",
    version = "1.2.0",
    deps = ["//packages/colors"],  # packages this one imports
)
```

```typst
#import "@acme/house-style:1.2.0": letter
```

A document or a library names the package in `deps`. The name, the
version and the namespace (`local` if not given) say where Typst finds
the package; the name and the version must be the ones in `typst.toml`,
and Typst says so if they are not.

## Packages from Typst Universe

In `MODULE.bazel`, name the packages documents import, and the file that
pins them:

```starlark
typst.package(name = "fletcher", version = "0.6.0")
typst.lock(file = "//:typst.lock.json")
use_repo(typst, "preview")
```

`@preview/fletcher:0.6.0` in Typst is then `@preview//fletcher:0.6.0` in
`deps`, and it brings the packages it imports itself.

Those are for fletcher alone. A document that imports one of them itself
names it in `MODULE.bazel` too; until then the label is not visible.

Typst Universe publishes no hashes and no list of what a package
imports, so the lock file holds both, for each package named and each
one those import. It is written for you:

```bash
bazel run @preview//:lock
```

That downloads the packages the file lacks, reads their sources for the
packages they import in turn, and writes the file, to be checked in.
Until then, a document that needs a package does not build, and says to
run this.

After that, Bazel downloads each archive once and checks it against its
hash. Compiling never downloads: a package that is not in `deps` is an
error.

The lock file is never edited by hand. To add a package, change its
version, or drop it, change the `typst.package` lines and run the same
command again: it pins what is new, keeps the hashes it has, and removes
what nothing asks for any more, down to an empty file when the last
package goes. Check both files in together.

To have a test say when the two disagree, compare the lock file with the
one the command would write:

```starlark
load("@bazel_skylib//rules:diff_test.bzl", "diff_test")

diff_test(
    name = "lock_test",
    file1 = "typst.lock.json",
    file2 = "@preview//:typst.lock.json",
)
```

## Inputs

One source can make several documents. `inputs` are strings the document
reads from `sys.inputs`:

```starlark
typst_document(
    name = "resume_short",
    main = "resume.typ",
    inputs = {"variant": "short"},
)
```

```typst
#let short = sys.inputs.at("variant", default: "full") == "short"
```

## Fonts

Fonts installed on the machine are never used. A document has the four
families inside Typst (Libertinus Serif, New Computer Modern and its math
font, DejaVu Sans Mono) and the font files it names:

```starlark
typst_document(
    name = "report",
    main = "report.typ",
    fonts = ["@inter//:fonts", "fonts/Logo.otf"],
)
```

A library names fonts the same way, and a document that depends on it
gets them. They can come from any repository, an `http_archive` of a font's release
for one. Typst tells fonts by their extension: `.ttf`, `.otf`, `.ttc`
or `.otc`.

## Other formats

`format` chooses what is written: `"pdf"` unless given, or `"html"`,
`"svg"` or `"png"`, as `<name>.html` and so on.

```starlark
typst_document(
    name = "figure",
    main = "figure.typ",
    format = "svg",
)
```

An SVG or a PNG is one page, and Typst refuses a document that has more.
For a file of each page, set `file_per_page`:

```starlark
typst_document(
    name = "slides",
    main = "slides.typ",
    format = "png",
    file_per_page = True,
)
```

That writes the directory `slides.pages`, holding `1.png`, `2.png` and
so on, or `01.png` to `12.png` when there are twelve, so that they sort.

A PNG has 144 pixels to the inch, or as many as `ppi` says.
Typst calls its HTML export unfinished, and warns so on every build.

## Reproducible output

The same inputs always give the same output. The clock is not one of
them:
the day a document says it was made, in a PDF and as
`datetime.today()`, is January 1, 1970 unless the rule names another:

```starlark
typst_document(
    name = "letter",
    main = "letter.typ",
    date = "2026-11-21",
)
```

## An example

`examples/resume` is a resume built four ways from one source: in
full, in short, as a picture, and as a web page. Its look is a library
that brings its own font.

Typst's HTML export leaves out what only a page has: grids, lines,
spacing. So the library asks `target()` which it is writing for, and
gives a browser headings and paragraphs where a page gets columns.

```bash
bazel build //examples/resume:all
```

[typst-bazel-examples](https://github.com/popovicu/typst-bazel-examples)
uses the rules as another module would: it gets them from GitHub, and
depends on a module of its own that offers a package.
